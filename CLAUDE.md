@AGENTS.md

## Project

A minimal ecommerce storefront built with Next.js 16 (App Router, Turbopack), React 19, TypeScript and Tailwind CSS v4. It is deliberately early-stage: catalog data (categories, products, stock) lives in PostgreSQL via Drizzle ORM, but there is no auth, cart, orders, payments, reviews, wishlist, product variants or admin yet. Don't add these unless asked.

## Commands

```bash
npm run dev      # dev server at http://localhost:3000
npm run build    # production build (also regenerates route types)
npm run lint     # ESLint (next core-web-vitals + typescript configs)
npm run format   # Prettier with Tailwind class sorting
npx tsc --noEmit # typecheck

npm run db:generate # create a SQL migration in drizzle/ from src/db/schema.ts
npm run db:migrate  # apply pending migrations to DATABASE_URL
npm run db:seed     # upsert the starter catalog (safe to rerun)
npm run db:studio   # browse the database
```

There is no test framework set up yet.

## Next.js 16 specifics

This Next.js version differs from older ones, and `AGENTS.md` asks you to check the bundled docs in `node_modules/next/dist/docs/` before writing Next-specific code. Things that matter here:

- **`cacheComponents: true`** is set in `next.config.ts`. Because of this, a build fails if a prerendered component reads non-deterministic values such as `new Date()` or `Math.random()`, or does an uncached dynamic data access. When you need one, use `"use cache"`, `await connection()` or a client component, as the build error suggests.
- **Route params are a `Promise`.** Use the global `PageProps<"/route/[param]">` and `LayoutProps<"/">` helpers and `await params`. These types are generated by `next dev` or `next build`. If `tsc` says a route literal doesn't satisfy the constraint, run a build first to regenerate them.
- **Tailwind** is loaded through the `@tailwindcss/turbopack` loader configured in `next.config.ts`, not through PostCSS. Theme tokens such as `--color-background` and `--color-foreground` are defined in `src/app/globals.css` with `@theme inline`.

## Architecture

- `src/app/layout.tsx` wraps every page in the shared `Header`, a full-width `<main>` and `Footer`; each page adds its own `container-page`. Page-level `metadata.title` values fill the `"%s | Store"` template.
- Remote images must be built with `unsplash()` from `src/lib/images.ts` so they match `images.remotePatterns` in `next.config.ts`.
- `/products/[slug]` uses `generateStaticParams` to prerender each product and calls `notFound()` for unknown slugs, which renders `src/app/not-found.tsx`.
- Prices are integers in minor units (cents) along with a `currency` code (see `src/types/product.ts`). Always display them through `formatPrice` in `src/lib/format.ts`.
- Import paths use the alias `@/*`, which points to `src/*`.

## Database conventions

PostgreSQL via Drizzle ORM (`postgres` driver). `DATABASE_URL` comes from `.env`. Full background is in `docs/database.md`.

- **Scope:** only `categories` 1─< `products` 1─1 `product_stock`. Don't add variants, orders, carts, reviews or wishlists until asked.
- **Schema changes:** `src/db/schema.ts` is the source of truth. Every change goes through `npm run db:generate` → review the SQL in `drizzle/` → commit → `npm run db:migrate`. Never use `drizzle-kit push` on a shared database, and never hand-edit generated migrations or `drizzle/meta/`.
- **Table and column style:**
  - snake_case column names, set explicitly (`text("image_url")`), with camelCase TypeScript keys;
  - `integer` identity primary keys;
  - a unique `slug` as the public identifier used in URLs;
  - `created_at` / `updated_at` as `timestamptz` with `defaultNow()`, and `updated_at` uses `$onUpdate`.
- **Money:** `integer` minor units (cents) with a `CHECK (>= 0)`, plus a `char(3)` currency.
- **Stock:**
  - stock lives in `product_stock` as a single `quantity` (`CHECK (>= 0)`), not on `products`;
  - only the number is stored; labels like "Sold out" are derived in `src/lib/stock.ts`.
- **Foreign keys:**
  - `products.category_id` uses `ON DELETE RESTRICT`;
  - `product_stock.product_id` uses `ON DELETE CASCADE`;
  - hide products with `is_active = false` rather than deleting them; reads return only active products.
- **Access:**
  - only data functions in `src/lib/` import `db` from `@/db`, which is `server-only`; pages and components never do;
  - data functions map rows to the types in `src/types/product.ts` rather than returning Drizzle rows.
- **Caching:**
  - every database read runs inside a `"use cache"` function with `cacheTag("products")` and/or `cacheTag("categories")` and `cacheLife("minutes")`;
  - after any write, call `updateTag` with the affected tag.
- **Seed:**
  - `src/db/seed.ts` upserts by `slug` and must stay safe to rerun;
  - update it whenever a required column is added.
- **Build:** `next build` needs a migrated and seeded database, because `generateStaticParams` for `/products/[slug]` must return at least one product. Run `db:migrate` before `build` in CI and deploys.
